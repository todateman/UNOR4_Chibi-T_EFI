# インジェクタ 無効噴射時間・流量 特性測定手順書

対象: Chibi-T ECU（UNOR4）用インジェクタ
関連リポジトリ: `UNOR4_Chtbi-T_EFI`（`develop/2026zenkoku` / `INJ_test`ブランチ）

## 1. 目的

インジェクタの噴射特性を次の一次式でモデル化し、実測により定数を決定する。

```txt
噴射量 V = 流量Q × (指令パルス幅 PW − 無効噴射時間 t_dead)
```

- **流量 Q**：単位時間あたりの燃料噴射量（ml/ms や g/min）
- **無効噴射時間 t_dead**：電圧印加から実際に弁が開くまでの実効遅れ（ms）

現状 `main.cpp` の `gasml += (((...)*0.0000007)+0.0015)/1.5073;` は、過去の実測シート（`燃料噴射時間・量`）の質量データを線形回帰した式（`0.0007*PW+0.0015`）を比重換算し、さらに出所不明の `1.5073` で割ったものと判明している。これを物理的に妥当な形（後述）に置き換えるのが最終目標。

## 3. 事前準備（過去データからの教訓）

過去シート `燃料噴射時間・量` のレビューで判明した、繰り返してはいけない失敗点：

- [ ] **メスシリンダは小流量で信頼できない**。500発合計でも数ml程度になるPW（3ms以下）では実測比重が0.83〜0.88など非現実的な値になった。→ **体積は参考値、質量を主データとする**
- [ ] **短いPW側のデータが不足すると回帰が破綻する**。実測データ(0.5〜10ms)を素直に回帰すると切片が正になり、無効噴射時間が負（≈−2ms）という物理的にあり得ない結果になった。→ **0.2〜0.5ms付近を複数点、必ず追加する**
- [ ] **反復回数が水準ごとに不揃い**。0.5msはn=1で再現性を確認できなかった。→ **全水準で最低3回反復**
- [ ] **燃圧が記録されていなかった**。→ **試験条件として必ずログに残す**
- [ ] **500発の連続噴射中に燃圧が垂れていた疑いがある**（PWが大きいほど区間傾きが下がる傾向）。→ **バースト前後で燃圧を確認、可能ならバッテリー電圧も記録**

## 4. 試験条件

- 燃圧： 規定値（例: 0.35MPa ）に調整し、燃圧計で記録。  
  運転中に変動の可能性があるなら、燃圧も調整しながら測定する。
- 燃料温度：可能なら記録（粘性・比重に影響）
- 供給電圧：バッテリー電圧を記録（無効噴射時間は電圧依存性がある）
- パルス幅の水準：**0.2, 0.3, 0.4, 0.5, 1, 2, 3, 4, 6, 8, 10 ms** を目安に、実運用域（巡航4.0〜4.4ms、始動8.0ms）前後を厚めに、かつ無効噴射時間が埋もれないよう短パルス側を必ず含める
- 各水準で**最低3回**反復
- 1水準あたりのパルス数 N：重量計の表示分解能は0.01gだが、これは「読み取れる最小桁」であって「実力精度（繰り返し精度）」ではない点に注意する。
  - 事前チェック：既知の小さな重り（1〜2g程度、なければ硬貨等で代用可）を風袋込みで10回程度計量し、ばらつき（標準偏差 or 最大−最小）を確認する。
    これを実効分解能 `d_eff` とする（表示分解能どおり0.01g前後で揃うか、それとも0.02〜0.05g程度ばらつくかを見る）。
  - 目標質量 = `d_eff / 0.02`（誤差2%以下を狙う場合の最低質量）、できれば `d_eff / 0.01` 以上（誤差1%以下）を集める。
    `d_eff`が事前チェックで0.01gと確認できれば最低0.5g・目安1g、0.05g程度までばらつくなら最低2.5g・目安5gとなる。
  - 低PWほど1発あたりの噴射量が小さいため、Nを多めに設定する  
    （目安：先に500発の試し打ちをして1発あたりの概算量を出し、目標質量からNを逆算する）

## 6. 手順B（補助・検証）：オシロスコープによる電流波形観測

- CH1：インジェクタ駆動端子（ドライバ段通過後、インジェクタ端子側）の電圧 → コマンド基準エッジ
- CH2：電流プローブでコイル電流波形を取得
- トリガ：CH1立下り、シングルショット。まず1ms/divで全体を見てから、立ち上がり直後を200〜500µs/divでズーム
- コイル電流の立ち上がり中に現れる**キンク（電機子リフトオフによる逆起電力の影響）**までの時間が開弁遅れ
- OFFエッジから電流が0になるまでの時間が閉弁遅れ
- 位置づけ：この結果はあくまで**手順Aの答え合わせ・物理現象の裏取り**。ECUコードの`calculatedINJ_time`基準で使うべき無効噴射時間の値は、手順Aの回帰から得る方が本質的に正しい（ドライバ段遅れも含めた正味の影響を捉えているため）

## 7. データ解析

1. 各パルス幅水準の質量データ（体積データではなく）を用いる
2. 「1回あたり噴射量[g] = 質量差 ÷ N」を算出
3. 全水準の (PW, 1回あたり噴射量) を線形回帰する
4. **切片の符号を必ず確認する**
   - 切片が負 → 妥当。t_dead = −切片／傾き で無効噴射時間が求まる
   - 切片が正 → 無効噴射時間モデルとして解釈不可。短パルス側のデータ不足を疑い、0.2〜0.4ms付近を追加測定してやり直す
5. R²を確認し、外れ値（燃圧変動・記録ミスの疑いがある点）がないか個別データも見る
6. 流量 Q [g/ms] を60000倍すれば g/min、比重で割れば ml/min

## 8. ECUコードへの反映

`gasml` の計算式を、物理的に素直な形に置き換える。

```cpp
// t_dead_us, flow_ml_per_us は本手順で実測した値
unsigned long duration_us = timeNow_INJ_OFF - timeNow_INJ_ON;
if (duration_us > t_dead_us) {
  gasml += flow_ml_per_us * (duration_us - t_dead_us);
}
```

同じ計算式が360CA安全リセット処理内にも重複しているため、そちらも合わせて置き換える。

## 10. 初回測定データの考察（2026-08-22実施分, `injector_test_log_20260822.csv`）

### 10.3 回帰結果

PW=0.2〜6msの27点（8,10msを除く全水準）で単回帰すると：

```txt
噴射量[g/300発] = 0.1767 × PW[ms] + 0.3165　　R² = 0.988
```

**切片が正**であり、t_dead = −0.3165 / 0.1767 ≈ **−1.8 ms** と物理的にあり得ない値になった。§3で報告済みの過去の失敗（切片正・t_dead≈−2ms）とほぼ同じ症状であり、今回0.2〜0.5msを追加しても解消していない。

### 10.4 原因の切り分け

- 逆にノイズの大きい0.2〜0.5msを外し、直線性の良い**PW=1〜6msのみ（15点）**で再回帰すると R²=0.992 と非常に良い当てはまりになる一方、t_dead ≈ **−2.2 ms** とむしろ悪化する。  
  → 単に短パルス側のデータが荒いだけでは説明できない。
- 使用した重量計（[YFFSFDC ポケットデジタルスケール](https://www.amazon.co.jp/dp/B07QQJ3BZG)）の表示分解能は実際には**0.01g**（§2参照。当初この考察で前提にしていた0.1gは誤り）。  
  この分解能を基準にすると、PW=1〜6msの各水準（噴射量1.03〜1.36g、N=300）は§4改訂後の目安（最低0.5g・目安1g以上）を十分満たしており、**Nはこの範囲では大きな問題ではなかった**可能性が高い。  
  不足が疑わしいのはPW=0.2〜0.5ms（噴射量0.29〜0.43g）のみ。
- PW=1〜6msの分解能に対して十分な質量が確保されていたにもかかわらずR²=0.992・切片正という結果が出ていることは、**単純な量子化誤差では説明しにくい**ことを意味する。  
  むしろ「**バーストごとに一定量のオフセットが乗っている**」（噴射量 = N×Q×(PW−t_dead) + C_burst、C_burstはバースト開始時のインジェクタ挙動やアキュムレータ圧の過渡応答による余剰噴射などPWによらない固定量）という仮説、あるいは重量計の実力精度が表示分解能（0.01g）より悪い（§4改訂で追記した「実効分解能 d_eff」の検証が未実施）という仮説の方が有力になった。

### 10.5 導出できたパラメータ（暫定・要検証）

- **流量 Q ≈ 33〜35 g/min ≈ 44〜47 ml/min**（密度0.754g/ml換算、燃圧0.33〜0.38MPa条件下、PW=0.2〜6msでの回帰による）。直線性は良好（R²=0.99前後）なため、Qの推定値としては信頼できる。
- **無効噴射時間 t_dead：有効な値は得られていない**（回帰切片が正のため）。§9のチェックリスト「回帰切片が負であることを確認」を満たしておらず、このまま`gasml`計算式（§8）には反映できない。

### 10.8 重量計 実効分解能の検証結果（1円硬貨10回計量）

§4の事前チェックを実施した結果：

```txt
0.98, 1.00, 0.98, 1.00, 0.99, 1.00, 1.00, 0.99, 0.98, 1.01 [g]（公称1.000gの1円硬貨、n=10）
```

- 平均 0.993g、標準偏差 ≈0.011g、レンジ(最大−最小) 0.03g（0.98〜1.01g）
- **繰り返し精度は表示分解能どおりほぼ0.01g級で良好**（安価なスケールとしては上出来）。ただし1回の読み取り単体では±0.01〜0.03g程度ばらつき得るため、実効分解能は `d_eff ≈ 0.02〜0.03g`（レンジを目安）として扱うのが安全側。
- 平均が公称値より約0.007g（0.7%）低い、**わずかな系統的なマイナスオフセット**が見られる。ただしこの種の一律オフセットは回帰の傾き・切片に比例的にかかるだけなので、t_dead=−切片/傾きという**比の値には影響しない**（10.4の切片正問題の説明にはならない）。気になる場合は今後、実測値を×(1.000/0.993)≈1.00705倍する補正、または計量前に既知の重りでスパン点を確認する運用を追加するとよい。
